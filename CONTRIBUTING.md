# Contributing

Read the project README and SECURITY.md before contributing. Discuss substantial architecture or scope changes in an issue first.

1. Create a focused branch from the current default branch.
2. Make a small, coherent change and preserve unrelated work.
3. Run appropriate checks and record the results.
4. Update documentation when installation, behavior, operations, or recovery changes.
5. Open a pull request explaining the problem, solution, validation, and rollback considerations.
6. Resolve review conversations before merging. When working alone, review your own diff and document validation.

Never commit credentials, private keys, real environment files, personal data, or unsanitized infrastructure exports. Use placeholders and approved secret storage. Test security tools only against owned or explicitly authorized systems.

Repository-specific instructions take precedence over these defaults. Maintainers decide acceptance and release timing; no response-time commitment is implied.
